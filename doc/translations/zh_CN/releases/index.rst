版本发布
########

Zephyr 以源代码和构建脚本的形式发布，而不是二进制镜像。使用 :ref:`west` :ref:`获取指定版本的代码 <get_the_code>`，并查看 `GitHub repository`_ 了解带标签版本的完整历史。

当前版本和历史版本的技术文档见 https://docs.zephyrproject.org/（可使用版本选择器选择你关注的版本）。

.. _zephyr_release_cycle:

版本生命周期与维护
******************

主要版本与维护版本
==================

Zephyr 按 **每六个月一次** 的节奏发布主要版本，目标月份为每年 4 月和 10 月。这一节奏既能提供经过充分测试的定期版本，又不会因更新过于频繁而让用户不堪重负，同时避开了各地的重大节假日。

当某个主要版本分支上积累了足够多的重要修复时，会不定期发布维护（点）版本。每个点版本在发布前都要经过完整的 QA 流程。

长期支持与维护
==============

稳定版本的支持期限为 2 个发布周期（约 1 年），而 Zephyr 项目会对部分特定版本提供更长时间的支持，这些版本称为长期支持（LTS）版本。

Zephyr :ref:`长期支持（LTS） <release_process_lts>` 版本每 2.5 到 3 年发布一次，从主开发树独立分支出来，并在发布后约 5 年内独立维护。

这为项目用户提供了更高的稳定性，也留出了更多时间升级到下一个 LTS 版本。


过渡到新的发布节奏
==================

过渡到新发布节奏的工作将于 2026 年开始。Zephyr 4.4 计划于 2026 年 4 月发布，此后将每六个月发布一次。

安全修复
========

Zephyr 中修复的每个安全问题都会向后移植或提交到以下版本：

- 当前受支持的长期支持（LTS）版本。

- 最近的两个版本。

更多信息参见 :ref:`安全漏洞报告 <reporting>`。

版本相关文档
************

每个版本包含两份配套文档：

- 版本说明汇总了发布周期内整个项目范围内的变更。
- 迁移指南描述了将应用从一个主要版本迁移到下一个主要版本时需要采取的行动。

版本说明
========

版本说明列出了发布开发周期内项目各个领域所做的变更。需要用户修改自身应用以适配新版本的变更也可能在版本说明中提及，但关于 *具体需要修改什么* 的细节会在该版本的迁移指南中详述。

发布周期结束后允许更新版本说明，但仅限于风格、排版修正，以及为了让最新文档与项目变更保持一致而合并维护版本分支说明的情况。

迁移指南
========

Zephyr 为所有主要版本提供迁移指南，以帮助用户从上一个版本过渡。

如上一节所述，需要用户采取行动（即修改源代码或配置文件）才能保持应用现有行为的代码变更，应写入迁移指南。这包括：

- 破坏性 API 变更
- 弃用
- 影响用户的 Devicetree 或 Kconfig 变更（默认值变更、重命名等）
- 具有影响的全树变更（例如修改包含路径，或默认改用不同的 C 标准库）
- 任何其他可能影响现有应用编译或运行时行为的内容

迁移指南中的每个条目都必须简要说明变更内容，并引用引入该变更的 Pull Request，以便用户理解变更的背景。
