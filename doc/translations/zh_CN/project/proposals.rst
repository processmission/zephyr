功能跟踪
########

向 Zephyr 项目提出新提案的步骤如下：

#. 首先搜索现有的 `议题 <https://github.com/zephyrproject-rtos/zephyr/issues>`_ ，了解该领域是否已有相关工作。
#. 如果没有，可以创建一个类型合适的 `新议题 <https://github.com/zephyrproject-rtos/zephyr/issues/new/choose>`_ （Enhancement、RFC/Proposal 等）。

如果你希望讨论现有议题的实现，或参与其实现工作，应联系该议题指定的负责人。

.. note::

   此前，项目使用 `GitHub 标签 <https://docs.github.com/en/issues/using-labels-and-milestones-to-track-work/managing-labels>`_ 跟踪功能相关的工作。你可能会看到带有“Feature”或“Enhancement”等标签的议题。

   新议题已不再使用这些标签，而应选择合适的议题类型。例如，应创建 Enhancement 类型的议题，而不是为新议题添加 Enhancement 标签。

路线图与发布计划
****************

项目路线图和发布计划都是项目的重要工具，但两者的用途截然不同，不应混淆。项目路线图传达项目战略的总体概况，而发布计划是一份战术层面的文档，用于记录和跟踪即将发布的版本所计划包含的功能。

- 项目路线图说明为什么做；发布计划详细说明做什么
- 发布计划仅涵盖几个月；产品路线图则可能涵盖一年或更长时间


项目路线图
==========

项目路线图应以可视化方式概括项目的战略目标和预期。

合理制定的路线图能在多个方面发挥重要作用。它可以帮助项目以有说服力的方式向现有和新的利益相关方展示计划，帮助招募新成员，也可以作为团队和社区在整个项目开发过程中随时查阅的实用资料，确保工作仍按计划推进。

因此，路线图应仅包含战略层面的细节、项目的主要主题、史诗级需求和目标。


发布计划
========

当项目路线图中的总体战略转化为可执行计划时，发布计划便开始发挥作用。这份计划以特定版本或里程碑需要纳入的具体功能、增强和修复为基础。

发布计划说明项目下一个版本（或接下来几个版本）预定包含的功能和增强。因此，它更像一份项目执行计划，将宏观构想拆分为较小的项目，供社区和项目的主要利益相关方逐步推进。
