TSC 工作组
**********

概述
####

TSC 可酌情设立工作组或小组委员会，作为专门负责特定技术领域、专项工作或任务的团队。

成员资格
########

工作组成员资格条件
++++++++++++++++++

- 各工作组（WG）应与 TSC 协商，自行确定成员资格条件。
- 各工作组应有一批积极参与其活动和决策过程的成员。
- 工作组成员资格原则上应 **向所有** Zephyr 项目 :ref:`协作者 <collaborator>` 开放；但工作组可以设置限制，例如限制来自同一家公司的参与人数。
- 所有 TSC 成员均有资格加入工作组，这也是 TSC 成员职责的一部分。
- 最低成员人数可根据任务的复杂程度以及有效完成任务所需的专业知识覆盖范围而有所不同。
- 工作组应力求至少有五至七名成员，以确保观点的多样性、协作和工作的连续性。
- Zephyr 项目内各工作组的组织结构应确保工作有效、高效且具有包容性。工作组的最佳规模可根据具体情况及其活动范围而有所不同。
- 工作组会议和讨论向所有项目 :ref:`贡献者 <contributor>` 开放。

工作组主席 / 联合主席
+++++++++++++++++++++

各工作组可选举一名主席，并可选择增设一名联合主席，负责主持会议并代表工作组与 TSC 沟通。

工作组主席 / 联合主席选举
+++++++++++++++++++++++++

- 主席和联合主席应由工作组成员选举产生
- 工作组的任何成员都有权自荐担任主席或联合主席。
- 主席和联合主席的任期为一年
- 如果主席或联合主席在任期届满前辞职，应举行投票，选举新的主席或联合主席。

工作组投票资格
++++++++++++++

- 工作组成员有权参与主席或联合主席的选举投票。
- 每家公司仅可有 1 名工作组成员在选举中投票。
- 主席和联合主席应为工作组成员。

工作组选举结果确认
++++++++++++++++++

- 当选的主席和/或联合主席须提交 TSC 确认。
- TSC 决定接受选举结果或要求重新投票。

咨询角色
########

- 工作组具有咨询性质，为各项目和 TSC 提供建议。
- 工作组以大致共识为基础开展工作。如果工作组无法就所要提出的建议达成共识，工作组主席应将该问题提交 TSC 或相关委员会（功能安全和信息安全委员会），由其进行正式投票，或告知项目工作组无法达成共识。
- 工作组应跟踪讨论，记录所有投票、决定或建议，并与社区和 TSC 分享结果。
- 工作组会议和线下讨论应记录在独立文档中，并包含所有相关细节，例如出席情况、法定人数、待执行的行动和后续步骤。
- 工作组内部作出的决策不具约束力，只有在向 TSC 通报决策和结果后，才可视为获得批准。
- 在通报或报告任何结果后的 1 周内，如果 TSC 未提出任何异议，则工作组的决策视为已获确认和批准。

TSC 工作组生命周期
##################

创建 TSC 工作组
+++++++++++++++

要创建 TSC 工作组，TSC 成员应通过 TSC 邮件列表向 TSC 提交提案，提案应至少涵盖以下内容：

- TSC 工作组名称。
- TSC 工作组宗旨
- TSC 工作组预期交付成果
- TSC 工作组初始参与者，其中至少有一名 TSC 成员担任发起人。
- 可选的 TSC 工作组完成标准

变更 TSC 工作组
+++++++++++++++

TSC 可以通过决议变更 TSC 工作组。如需申请此类变更，应向 TSC 邮件列表提交请求。

终止 TSC 工作组
+++++++++++++++

TSC 按照其决策程序决定是否终止 TSC 工作组。提交的终止 TSC 工作组请求应涵盖以下内容：

- TSC 工作组名称
- TSC 工作组交付成果
- 终止 TSC 工作组的理由
