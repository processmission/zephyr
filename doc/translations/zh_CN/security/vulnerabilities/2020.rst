:cve:`2020-10060`
-----------------

UpdateHub 可能解引用未初始化的指针

在 updatehub_probe 中，JSON 解析完成后，代码会从输出结构中的两个不同位置访问 objects\[1]。如果 JSON 包含的元素少于两个，该访问将引用未初始化的栈内存。这可能导致崩溃、拒绝服务，甚至可能造成信息泄露。

建议在修复可用之前禁用 updatehub。

参见 NCC-ZEP-030

此问题已在针对 Zephyr main 的 PR 中修复。

:cve:`2020-10062`
-----------------

MQTT 中数据包长度解码错误

CVE：Zephyr 项目的 MQTT 数据包长度解码器中存在差一错误，可能导致内存损坏并可能造成远程代码执行。NCC-ZEP-031

MQTT 数据包头长度可以为 1 到 4 字节。代码中的差一错误可能导致其被解释为 5 字节，从而引发整数溢出，导致内存损坏。

此问题已在 main 中针对 v2.3 修复。

- `Zephyr 项目缺陷跟踪系统 ZEPSEC-84 <https://zephyrprojectsec.atlassian.net/browse/ZEPSEC-84>`_

- `v2.3 的提交 11b7a37d <https://github.com/zephyrproject-rtos/zephyr/pull/23821/commits/11b7a37d9a0b438270421b224221d91929843de4>`_

- `NCC-ZEP report`_ (NCC-ZEP-031)

.. _NCC-ZEP report: https://research.nccgroup.com/2020/05/26/research-report-zephyr-and-mcuboot-security-assessment

在 Zephyr LwM2M 实现中，格式错误的输入可能导致无限循环，从而造成拒绝服务攻击。

- `Zephyr 项目缺陷跟踪系统 ZEPSEC-56 <https://zephyrprojectsec.atlassian.net/browse/ZEPSEC-56>`_

- `v2.4 的修复 PR26571 <https://github.com/zephyrproject-rtos/zephyr/pull/26571>`_

- `v1.4 的修复 PR33578 <https://github.com/zephyrproject-rtos/zephyr/pull/33578>`_

:cve:`2020-13603`
-----------------

mempool 中可能发生溢出

 * Zephyr 则提供了预构建的 'malloc' 包装函数作为替代。
 * 'malloc' 函数是 'sys_mem_pool_alloc' 函数的包装函数。
 * sys_mem_pool_alloc 以不安全的方式分配 'size + WB_UP(sizeof(struct sys_mem_pool_block))'。
 * 请求非常大的 size 值会导致内部整数回绕。
 * 整数回绕会导致成功分配到的内存非常小。
 * 例如：调用 malloc(0xffffffff) 会成功分配 7 字节。
 * 这会导致堆溢出。

- `Zephyr 项目缺陷跟踪系统 ZEPSEC-111 <https://zephyrprojectsec.atlassian.net/browse/ZEPSEC-111>`_

- `v2.4 的修复 PR31796 <https://github.com/zephyrproject-rtos/zephyr/pull/31796>`_

- `v1.4 的修复 PR32808 <https://github.com/zephyrproject-rtos/zephyr/pull/26571>`_
