.. _sensor-read-and-decode:

读取与解码
##########

用于读取传感器数据且正在快速趋于稳定的 API 包括：

* :c:func:`sensor_read`
* :c:func:`sensor_read_async_mempool`
* :c:func:`sensor_get_decoder`
* :c:func:`sensor_decode`

相比 :ref:`sensor-fetch-and-get` 的优势
***************************************

这些 API 拓展了传感器的使用方式，支持更多传感器类型以及涉及传感器的数据流。这些是 Zephyr 面向未来的 API，解决了使用 :ref:`sensor-fetch-and-get` 时遇到的诸多问题。

:c:func:`sensor_read` 及类似函数将传感器的编码数据采集到调用者提供的缓冲区中。随后，解码操作（ :c:func:`sensor_decode` ）将传感器特定格式的编码数据解码为定点 :c:type:`q31_t` 值，并按通道组织为向量。这样便可使用处理数据向量的定点 DSP 函数进行进一步处理（例如低通滤波、FFT、融合等）。

读取操作默认采用异步实现，并利用 :ref:`rtio` 将异步请求串联起来，或从单个调用上下文中同时向多个传感器发起请求。

这使得处理传感器时可以采用非常实用的代码流程，例如：

* 获取原始传感器数据后，可以不解码、稍后解码，或在另一个处理器上（例如手机）解码。
* 直接从中断处理程序中发起传感器读取。无需专用线程，从而节省宝贵的栈空间。无需工作队列，从而避免引入不确定的延迟。从单个调用上下文（中断、线程或工作队列）中同时发起多个传感器的读取。
* 针对乒乓缓冲（双缓冲）配置，向同一设备发起多次读取请求。
* 构建从传感器开始的完整数据流流水线，以支持软件定义的虚拟传感器（ :ref:`sensing` ），所有处理均可在单个线程中按照有向无环图（DAG）确定的顺序执行。
* 还可以预先配置 DMA，使其由 GPIO 事件触发，从而在处理 FIFO 水位等传感器事件时完全无需 CPU 参与。

此外，还解决了 :ref:`sensor-fetch-and-get` 在内存和触发器处理方面的其他不足。

* 触发器会产生入队事件，而非调用回调函数。
* 触发器可配置为自动获取数据，还可以通过 GPIO 中断启动预先配置的 DMA 传输。
* 大幅降低因回调函数和上下文切换长时间屏蔽中断而遗漏触发事件的可能性。
* 通过将 FIFO 触发器关联到读取操作，将数据读入内存池分配的缓冲区，从而支持传感器 FIFO。
* 所有传感器处理均可在用户模式（受内存保护）的线程中完成。
* 更好地支持多个相同类型的传感器通道。

.. note::
   要充分发挥 `读取与解码`_ 的优势，需要通过符合 :ref:`rtio` 要求的通信接口访问传感器。通常，这意味着需要支持 :ref:`rtio` 的 SPI 或 I2C 总线驱动。

轮询读取
********

使用 `读取与解码`_ 进行轮询读取时，可以为传感器实例化一个轮询 I/O 设备（类似于文件描述符），并指定要轮询的通道。随后发起阻塞或非阻塞读取请求，再根据需要将数据解码为定点值。
